# CouchGraph

> Primary project skill and orchestration entrypoint for **CouchGraph**.

---

## 1. Goal

Serve as the central orchestrator and architectural contract for the CouchGraph codebase, classifying agent tasks, enforcing core invariants (UUIDv7, schema-first GraphQL, thin resolvers, DataLoader batching), and routing execution to specialized workflow skills.

---

## 2. Scope

- **Applies to**: All modifications, feature additions, refactors, documentation updates, and operational tasks in the `couchgraph` repository.
- **Tech Stack**: Go 1.26+, `gqlgen` v0.17+ (GraphQL schema-first), `kivik` v4 (CouchDB driver), CouchDB 3.x, `viper`, `zap`.

---

## 3. Core Invariants & Hard Rules

1. **UUIDv7 Primary Key Mandatory Rule**:
   - Every document `_id` generated by CouchGraph MUST use **UUIDv7** (`uuid.NewV7()`) to guarantee time-ordered lexicographical sorting.
   - Never use UUIDv4 or v5 for resource IDs unless explicitly requested for non-sortable use cases.
2. **Schema-First GraphQL**:
   - The GraphQL schema at `internal/graph/schema/*.graphqls` is the single source of truth for the API contract.
   - Run `gqlgen generate` whenever the schema changes. Never edit `internal/graph/generated/` or `internal/graph/model/` directly.
3. **Thin Resolvers & Layer Separation**:
   - Resolvers in `internal/graph/resolver/schema.resolvers.go` MUST only handle transport-level marshalling and delegate all business logic to `internal/couch/repository.go`.
4. **N+1 Prevention via DataLoader**:
   - Multi-document lookups by ID MUST use `couch.Loader` (`internal/couch/dataloader.go`) which batches requests into CouchDB's `_bulk_get` endpoint.
5. **Generic Document Scalar**:
   - Dynamic document payloads are exposed via the `Map` scalar (`internal/graph/scalar/map.go`) backed by `any` / `map[string]any`.
6. **Zero-Warning Builds**:
   - All code changes must pass `go build ./...`, `go vet ./...`, and `go test ./...` with zero errors.

## 4. Orchestrator Procedure

When an agent is invoked on this repository:

1. **Classify**: Match the user request against the [Routing Matrix](file:///Users/ton/work/couchgraph/skills/couchgraph/reference/routing-matrix.md).
2. **Extract Constraints**: Read the hard invariants above and any relevant domain boundary docs.
3. **Select Workflow**: Load the mapped workflow contract under `workflows/` (e.g., `/radioactive` for full features, `/document` for doc edits, `/review` for quality auditing).
4. **Execute**: Follow the deterministic procedure defined in the chosen workflow's `SKILL.md`.
5. **Validate Gate**: Run build/test checks before finalizing work.
